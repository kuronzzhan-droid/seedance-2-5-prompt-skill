# Seedance 2.5 视频提示词（4–30 秒，重点 30 秒）

Seedance 2.5（2026 年 7 月底发布）单次可以直出 4–30 秒的有声视频，最多带 50 个多模态参考素材，支持整数秒时间戳、视频编辑和视频延长。30 秒是 2.0（上限 15 秒）的两倍长，难点也变了：从“画面好不好看”变成“这 30 秒里每一段在干什么”。只描述一个画面然后拉长到 30 秒，模型会重复动作、中段漂移、乱切镜头。所以核心是：**分段预算 + 每段只推进一个变化 + 每段写清看得见的结束状态**。

这个技能按一位用户定制：他用即梦做说日语的成年男性兽人角色的 30 秒短片，文戏多，也有打戏，喜欢运镜和特写。给别人写通用题材时，跳过标着“这位用户”的部分即可。

## 交付格式

默认按这个顺序交付；用户说“只要提示词”时，只给第 3、4 项：

1. **方案一句话**：核心事件、结构（一镜到底分 N 段 / N 个镜头）、关键假设。用户已经给了完整分镜时可以省略。
2. **素材清单**：要上传哪些素材，按角色首次出场的顺序编号，各自负责什么。没有素材就写“纯文生视频，可直接用”。只引用用户真有的素材；本条用不上的素材建议不上传。
3. **完整提示词**：放在一个 `text` 代码块里，只写可以直接提交的内容：画面、镜头、声音、台词和时间段。画幅、总时长、分辨率、帧率和声音开关不写进提示词〔官方 sd25-pe〕。
4. **平台设置**：画幅、时长、分辨率、是否开启声音，写在代码块外面。默认先出 480P 样片，满意再出 720P；即梦页面默认是样片模式，出正式片前要手动切换〔用户记录；本地实测〕。编辑、首尾帧、延长任务会自动锁定部分参数，用户的要求和锁定规则冲突时，加一行“参数提示：”说明提交前怎么改〔官方 sd25-pe〕。
5. **台词草稿**（只在用户没给台词原文时出现）：1–2 句符合角色语气的日文建议，附中文意思和拍数，开头标明“草稿，未写进提示词”；用户确认后再放进 {}。
6. **可调整项**（可选，最多 3 条）：用户最可能想换的地方，比如结尾画面、某一镜的景别、要不要配乐。

提示词用中文写，日语台词保留日文原文。用户在海外平台使用或要求英文时，用 `references/templates-30s.md` 末尾的英文骨架。

## 工作流

### 0. 先读这位用户的档案

给这位用户写提示词之前，先读 `references/creator-profile.md`（个人档案，公开仓库里没有；本地使用时自己放进 references/，找不到就跳过，按用户在对话里给的信息写）：三条系列线的画幅、画风行、视角和台词语言，角色的识别特征、声线和口癖，他固定的分段顺序和常用镜头，以及他踩过的坑。档案没写的外观细节写成“以@图片N为准”，不替用户补设定。再按任务读：

- 有台词的兽人文戏：`references/kemono-jp-drama.md`
- 打戏、特写、有冲击力的运镜：`references/combat-closeups.md`
- 30 秒切几个镜头，想要日式动画 / 电视剧 / 电影的镜头感：`references/shot-grammar.md`
- 想从成品改起：`references/templates-kemono.md`（六条按他的固定分段写好的 30 秒模板）

### 1. 识别入口

只有想法 / 有人物、产品、场景图 / 有参考视频（先确认要借的是动作、运镜、节奏还是转场，不要默认全部照搬）/ 有脚本（保留故事、对白和结尾，补齐视觉和时序）/ 有精确分镜（保留秒数、顺序和素材分工，只补缺项、指出冲突）/ 编辑已有视频 / 延长已有视频 / 首尾帧或关键帧。入口可以混合。

### 2. 只问会改变成片的问题

最多一轮、最多 3 个问题：想拍什么事件、最后停在哪个画面？多长、横版还是竖版、什么风格？有哪些素材，哪些必须保留？

用户的描述已经覆盖了这三组的大部分时，就不要再问：直接写，把替用户做的假设列在方案里，请他纠正。只有事件、结尾或素材分工完全不清楚时，才停下来问。

用户说“直接写”，或者只缺少量信息时，用默认值，并在方案里标注：
- **这位用户**：按 `references/creator-profile.md` 第 1 节的系列默认值（海崖主线 16:9、超写实电影画面、第一人称；《兜风日》21:9、三渲二赛璐璐；《量身》21:9、手绘西幻插画），每条 30 秒，画幅和时长只写进平台设置。《量身》的视角档案里没记录，先问；用户说“直接写”就按第三人称写，并标成假设。
- **其他用户**：时长没说、内容又简单时，建议 10–15 秒；画幅 16:9；画风写成看得见的特征，例如“写实电影质感：自然光，浅景深，色彩克制”。
- 声音默认写“声音只有环境声、动作声和台词”，画面默认写“画面是纯净的影像”。

默认不配乐，因为模型随机生成的配乐很难去掉，也容易和剪辑节奏打架，后期配乐更可控。用户要音乐，就用 () 写清曲风、速度和起止秒，例如“(舒缓的钢琴独奏，约70 BPM，第25秒渐弱结束)”，同时把声音那句改成包含音乐的写法，前后保持一致。

### 3. 先设计，再动笔

1. **一句话故事**：一个主要人物 + 一个主要地点 + 一个清晰目标 + 一次主要转折 + 一个结尾画面。30 秒能讲好的故事就这么大；人物、场景和事件塞多了，每一样都会变糊。
2. **选结构**：
   - **一镜到底**（连续长镜头）：按时间段分 3–4 段，提示词写“一镜到底：镜头从第一秒到最后一秒连续运动，全程是同一个连续镜头”。用时间段描述，不写“镜头1 / 镜头2”，后者会被理解成要切镜〔单一来源〕。段与段的交界最容易被切开：2026-10-28 在即梦实测一条 30 秒早餐铺一镜到底，第 7.38 秒正好卡在“0–7秒”和“7–15秒”的交界，出现全片唯一一次硬切，从门外直接跳到店内〔本地实测，单次；当时的提示词还带着参数和负向约束〕。所以第二段起每段开头写“镜头不停，继续……”，跨空间时写出镜头的穿越路线，例如“镜头不停，继续跟着师傅跨过门槛进入店内，从他身后绕到他的右前方”。连续性要求很高时减到 3 段，或者拆成两条用延长接起来。这套写法还没复测，看样片时重点看各段交界处。
   - **多镜头剪辑**：5–9 个镜头，每个 2–6 秒，写成“镜头N（a–b秒）”，镜头之间写“硬切”。这位用户的固定写法就是按秒分五到九个镜头〔用户记录〕；官方 30 秒示例是 9 个镜头，时长依次为 3/3/4/4/4/4/3/3/2 秒〔官方〕。每多一个镜头，就多一次出错机会。
   - **对白戏优先多镜头**：对白的一镜到底长镜头，社区实测 3 次都没能同时做到台词时机准确和结尾静默〔单一来源：drama-skills 实测〕。
3. **分配时间**：见下文“时间轴”。每段只安排一个主要变化。
4. **写结束状态**：每段结尾写一句“画面里能直接看到的状态”（人站在哪、手里拿着什么、镜头停在什么景别），下一段从这个状态接着走。这是 30 秒不漂移的关键。多镜头硬切时，时间和地点可以跳（比如玄关 → 厨房），但服装、道具位置和左右站位要延续；地点变了，就在下一个镜头开头写清新地点。
5. **对白账本**（有台词、旁白或音色参考时，动笔前自己核对，不放进提示词）：每个时间段记一行：说话人、画内还是画外、对谁说、台词原文、语言、拍数和最短时长、用哪段音频、其他在场的人在做什么。逐段核对：每句只出现一次；每段最多一个说话人；指定了要说话或用某段音频的段落，没有被写成静默；说话人和音频没有对调；台词都来自用户的原文；一条最多两段音色参考〔官方 sd25-pe；用户记录〕。示例账本见 `references/kemono-jp-drama.md` 3.4。

### 4. 按固定分段写

官方推荐的顺序是：素材指代 → 一句话概述 → 分段情节（时间戳或“镜头 N”）→ 贯穿全片的机位、环境、声音和氛围〔官方〕。这位用户的固定分段和它兼容，默认按他的顺序写：画风 → 参考图 → 角色 → 场景布局 → 光 → 声音 → 按秒分镜 → 环境声〔用户记录〕。

```text
【画风】___（写看得见的特征：媒介、线条、上色、光影。这位用户三条线的画风行见 creator-profile.md 第 1 节，原样复制）
（可选）一句话概述：___在___，___，最后停在___。
【参考图】（没有素材就删掉这一段；一份素材一行，起一个短名字）
@图片1（___·头）：只照___头部的毛色、眼睛、耳形和吻部长短。
@图片2（___·全身）：只照___的服装、配饰和全身比例。
@图片3（___）：只照___的空间布局、材质和光线。
@音频1（___的音色）：只提供___的音色、语速和语气，台词以文字为准。
【角色】全片只有___和___两个角色，每人在画面里各只有一个。
___：___兽人，成年男性，___（物种结构）；只属于他的特征：___。外观以@图片1、@图片2为准，___使用@音频1的音色。
___：……（每个出场角色单独一行）
两人的毛色、服装和识别特征始终各归各的。
【场景布局】___在___的___侧，___在___的___侧；镜头始终在两人连线靠___的一侧。
【光】主光源在画外___侧，___。
【声音】声音只有环境声、动作声和台词。全片共___句台词，同一时间段只有一个人开口。画面是纯净的影像。
【分镜】
镜头1（0–___秒）：___景别，机位在___高度，朝向___，镜头___；地点：___。前景___，背景___。___（一串连续的小动作）。会动的细节：___。神态：耳朵___，视线___。结束时：___。
镜头2（___–___秒）：硬切，承接上一镜：___。角色名（日语，音色，情绪，对谁说）：{台词原文}___闭着嘴静静听。结束时：___。
……
【环境声】0–30秒：<___>一直持续到最后一秒；第___秒<___>。
```

- 一镜到底：把【分镜】换成按时间段写的【分段】，第二段起每段开头写“镜头不停，继续……”。
- 用户没给时间段、也没要求按秒控制时（见“时间轴”），把【分镜】换成“阶段一：开始时：……；主要事件：……；结束时：……”。
- 已经上传、本条却用不上的素材，在【参考图】后面加一行【未采用素材】，逐个列编号：“@图片4、@音频2在本条闲置；本条的人物、场景、道具、动作、镜头和声音只取自上面分配了职责的素材。”〔官方 sd25-pe 要求逐个列出；正向写法是这里的改写，未单独测试〕
- 其他题材：把角色行换成外观、服装和标志性道具；有素材就写“外观以@图片1为准”，不重复描述。

完整示例：这位用户的题材见 `references/templates-kemono.md`；一镜到底叙事、9 镜头剧情、产品广告、口播、动作、音乐卡点、首尾帧、编辑、延长、拼接和英文骨架见 `references/templates-30s.md`。读和需求最接近的一节，借结构，不照抄内容。

### 5. 交付前自检

- 提示词里没有画幅、总时长、分辨率、帧率和声音开关，这些都在平台设置里；时间段照写〔官方 sd25-pe〕。
- 提示词全是正向写法：要排除的东西写成“只有……”“全片保持……”；没有自动加用户没要求的画质、稳定、水印、字幕、分身之类的约束〔官方 sd25-pe；用户记录〕。
- 时间轴从 0 连续到总时长，各段加起来等于总时长；每段只有一个主要变化、一个主运镜，主体运动和相机运动分开写；每段都写了“结束时：……”。
- 一镜到底：第二段起每段开头写了“镜头不停，继续……”，跨空间写了穿越路线〔本地实测〕。
- 素材：编号和上传顺序一致，按角色首次出场排序；一行只绑一个角色、道具或场景；每份写了“只照哪一部分”；已上传但没用上的素材逐个列进了【未采用素材】〔官方 sd25-pe〕。
- 人数、服装、道具归属、左右站位全片连续；每个兽人角色写了物种结构和一个只属于他的特征，背景人物写了种族〔用户记录〕。
- 每个镜头的站位按机位写了前景和背景；没有三人以上在同一镜头里轮流说话〔单一来源：drama-skills 实测〕。
- 对白账本逐段核对过：每句台词都来自用户的原文，全片只写一次，写在自己的时间段里；同一段只有一个人开口，其他人闭着嘴；日语台词的拍数放得下〔官方 sd25-pe；推论〕。
- 先因后果：观众先看清触发原因，再看到反应特写〔官方 sd25-pe〕。
- 首尾帧、关键帧用的是独立的“@图片N作为首帧。”“@图片N作为尾帧。”〔官方 sd25-pe〕。
- 声音：音乐 ()、音效 <>、台词 {}；环境声写到最后一秒；声音设定前后一致〔官方；用户记录〕。
- 结尾有明确的停留画面；“高级感、电影感、丝滑”这类空话，换成了具体的镜头描述。

## 30 秒核心技巧

### 时间轴：按秒分镜，还是不带数字的阶段

- 这位用户的固定写法是按秒分五到九个镜头，这是他明确要的数字时间段，照写〔用户记录〕。Seedance 2.5 响应整数秒的时间戳，2.0 只响应镜头序号〔官方〕。
- 数字时间段用整数秒，从 0 连续写到总时长，不重叠、不留空。有三种写法：区间（“0–3秒”）、时间点（“第5秒”）、相对时间（“3秒后”）〔官方〕。段内的关键瞬间（一次撞击、一个卡点）可以再用“第 X 秒”单独标注。
- 时间段是事件预算，不是逐帧的剪辑点。社区实测切点会偏 0.3–0.5 秒，写小数秒没有意义〔单一来源：drama-skills 实测〕。也不用时间戳控制频次（如“一秒摇头 3 次”）〔官方〕。
- 每段的内容量要和时长匹配：内容太少，模型会自由发挥；太多，会过度剪切或漏掉剧情。事件太密时，合并次要事件、减少段数，而不是继续细分〔官方〕。
- 用户没给时间段、也没要求按秒控制时，按官方 sd25-pe 用不带数字的“阶段一 / 阶段二 / 阶段三”，每阶段只写一个主要状态变化。不要只因为平台时长是 30 秒，就自己造出“0–8秒”这类时间段〔官方 sd25-pe〕。
- 用户给的秒数加起来和平台时长对不上时，先指出来，请他选是改秒数还是改平台时长〔官方 sd25-pe〕。

### 常用 30 秒时间分配

| 类型 | 分配 |
|---|---|
| 一镜到底叙事 | 0–7 建立 / 7–15 推进 / 15–23 转折或高潮 / 23–30 收尾停留 |
| 四段式 | 0–6 交代场景 / 6–14 中景跟拍推进 / 14–23 特写或变化形成高潮 / 23–30 结尾 |
| 三幕式 | 0–8 铺垫 / 8–20 发展和转折 / 20–30 高潮和结局 |
| 产品广告（问题 → 解决） | 0–3 钩子 / 3–9 痛点场景 / 9–15 产品出场 / 15–20 关键转折 / 20–26 情绪高点 / 26–30 产品落版 |
| 故事型品牌广告（产品后半段才出场） | 0–3 钩子 / 3–11 铺垫 / 11–17 情感转折和台词 / 17–22 产品自然出场 / 22–26 情绪高点 / 26–30 产品落版 |
| 剧情 9 镜头（官方示例） | 0–3 / 3–6 / 6–10 / 10–14 / 14–18 / 18–22 / 22–25 / 25–28 / 28–30 |

镜头数的参考：用 2,356 部电影的镜头数据复算，30 秒文戏约 5 个镜头（每镜约 6 秒），吉卜力式的动画约 6 个，动作戏约 9 个（每镜约 3.3 秒）；两人同框的镜头比单人镜头停得久，景别越近停得越短〔多来源：DataReel 复算〕。每个时间窗至少留约 3 秒；冲击帧这类 1 秒以内的瞬间写进同一个窗口，不单独占一段〔单一来源：visual-skills〕。表格只是起点：用户自己给了故事顺序，就按用户的顺序分配。中段（约 12–20 秒）最容易重复动作或漂移，一定要给它一个具体的变化和一个明确的相机动作。

### 素材（全模态参考）

- 编号按上传顺序（@图片1、@视频1、@音频1）。多个角色按首次出场的顺序上传，编号跟着出场顺序走；名字在提示词里绑定，不靠图上写的字〔官方〕。
- 一行只定义一个角色、群体、道具或场景，以及它用哪几份素材。写“凯尔对应@图片1、@图片2”“杰拉德对应@图片3、@图片4”，不写“凯尔和杰拉德参考@图片1至@图片4”这种范围句〔官方 sd25-pe〕。同一角色用了几张图（头部 + 全身）时，写明这几张共同定义这一个角色，画面里只有一个他。每个出场角色用他自己的单人图〔官方 sd25-pe〕。
- 每份素材写“只照哪一部分”，例如“@图片1（凯尔·头）：只照凯尔头部的黑色毛发、琥珀色眼睛和耳形”“@视频1：只参考打斗动作和镜头节奏，人物外观以@图片1、@图片3为准”〔官方要求写清参考什么；“只照”是用户自己的写法〕。场景图或参考视频里有人时，在【角色】里写死“本条画面里的人物只有凯尔和杰拉德”；人物还是被带进来时，再按官方原句加“不采用图中人物”（负向写法，排障用）。
- 素材已经足够准确时，只做指代（“严格参考@视频1的动作和运镜，顺序与视频一致”），不再复述细节，复述的文字可能和素材打架〔官方〕。
- 常用分工：人物图定脸、毛色、服装；商品图定包装、材质、logo 位置；场景图定空间、色调、光影；参考视频定动作、运镜、节奏；音频定节拍、氛围、音色。
- 音色参考：一条最多绑两段，说话一人一镜〔用户记录〕；每段 5–10 秒、单人干净人声的效果较好〔官方；多来源〕。绑定写“图片1、图片2是凯尔，凯尔使用@音频1的音色”；音频只提供音色、语速和语气，台词内容以文字为准〔官方 sd25-pe〕。只用自己录的或有授权的声音。
- 数量：上限是图片 30 张（单张 4K 以内）、视频 10 段、音频 10 段，总共 50 份，音频和视频的总时长都不超过 30 秒；超过上限时，在回复里加一条“素材提示：”说明提交前要删哪些〔官方〕。稳定区间：主体图 1–8 个主体；主体音视频 1–5 个主体，每段 5–10 秒〔官方〕。这位用户的常规配置（每个出场角色头部和全身各一张、场景一张、音色最多两段）在这个区间内。素材越多，越要写清分工。
- 同一主体的多个视角，拆成多张单视图图片上传，比拼成一张图效果好〔官方〕。图片宽高比保持在 0.4–2.5 之间〔官方；用户记录：Pippit 超出会报错〕。出现指纹状纹理时，把输入图缩到不超过输出分辨率〔官方排障建议〕。
- 真实动物（宠物、坐骑、普通的鸟）的照片：只照品种、毛色花纹、耳朵和体型，最好是全身照〔推论〕。兽人角色不按动物处理，写法见下面的“兽人角色”。
- 没有参考图的角色：给 2–3 个固定的外观锚点（毛色或发型、衣服的颜色和材质、一件配饰），写“全片穿同一套___”，少给脸部特写。这位用户的角色每条都要附自己的参考图，角色行整段重写，不写“同上一条”〔用户记录〕；需要更稳时，先用 GPT Image 出参考图。
- 首尾帧：首帧、尾帧各用一句独立的角色句，写在提示词最前面：“@图片1作为首帧。”“@图片2作为尾帧。”。每句后面另起一句，写这张图定义什么，例如“该首帧定义两人的站位、朝向、道具位置和镜头方向。”〔官方 sd25-pe〕。首帧决定输出画幅，首尾帧要同画幅，否则尾帧会被拉伸〔官方〕。注意：在全能参考模式里只写“@图片1作为首帧”只会相近、不会锁定；要锁死开场画面，用平台的首尾帧模式（API 里 role 为 first_frame / last_frame）〔官方：相近但不完全一致；社区实测相似度偏低〕。
- 多关键帧：第一句写“以@图片1至@图片N的顺序作为关键帧。”，再逐张写“@图片2定义第二个关键帧：___（这一刻看得见的状态）。”，各帧之间写连续动作〔官方 sd25-pe〕。关键帧是要经过的状态，不是要停住的画面；独立的单张图比宫格拼图对齐得更准〔官方〕。
- 宫格分镜：15 格以内，用简洁线稿或火柴人，少写字〔官方〕。第一句写“@图片1提供九宫格分镜的镜头顺序和大致构图，按从左到右、从上到下的顺序读取，只采用镜头顺序和构图。”，再写整体故事梗概，最后逐格补齐分镜图里没有的动作、运镜和风格。要严格对齐就改用关键帧〔官方〕。用 GPT Image 出分镜时，另出一版纯画面的图（去掉对白气泡和文字），图上的字可能被带进视频〔官方〕。
- 白模 / 3D 预演：写明参考白模的哪些元素（运镜、动作、光影），并把每个几何体对应到具体的主体或道具；要参考白模的光影变化时，显式写“参考光影变化”〔官方〕。

### 兽人角色（这位用户的主角）

兽人是直立、穿衣、会说话的角色，不按“动物”处理：表演、台词和吻部口型都照角色来写。展开写法见 `references/kemono-jp-drama.md` 第 1 节。

- 物种写成看得见的结构，再加一个只属于他的特征，每次提到他都带上。例如“凯尔：黑狼兽人，成年男性，完整的狼头和长吻部，全身覆盖黑毛，直立双足，手是犬爪手（四根手指加一根拇指）；只属于他的特征：红围巾。外观和服装以@图片1、@图片2为准。”〔用户记录；物种结构的写法是推论〕
- 体型交给参考图，不写体型形容词；档案没写的细节写成“以@图片N为准”〔用户记录〕。
- 姿势写具体：“单膝跪地，上身挺直”。写“半蹲”会被画成四肢着地〔用户记录〕。
- 下水、游泳时写“贡纳尔在水里保持@图片N里的兽人体态和服装：上身直立，双臂划水”；他下水时被画成过真虎鲸〔用户记录〕。
- 背景人物逐个写种族，例如“酒馆里的客人是两个熊族水手和一个狐族侍者”；泛称的路人会被画成人类〔用户记录〕。
- 长得像的角色（赛伦和席尔、坐骑和骑手）尽量不同框；同框时写清各自相对桌子、门这类固定物体的位置，要换前后顺序就写出走位〔用户记录〕。
- 眼睛写成“眼睛是@图片1里的琥珀色动物眼，带柔和的眼神光”（颜色按档案或参考图）；写“正常人眼”可能在兽脸上画出人眼〔推论〕。
- 片中另有真实动物时，台词只给角色，例如“台词只由骑手说；坐骑是普通的马，嘴巴自然闭合，偶尔打响鼻”〔推论；官方要求写清说话人〕。

### 运镜和镜头语言

- 一段只用一个主要运镜（推、拉、摇、移、跟、环绕、升降、手持、固定），写清方向和速度。同一段里叠加推进、环绕和升降，模型会顾此失彼。
- 主体运动和相机运动分开写，如“人物向画面右侧走，镜头向左平移跟随”。
- 站位按机位写前景和背景，例如“前景是凯尔左肩和耳廓的虚影，背景是杰拉德的胸像”。社区实测只写“隔桌相对”9 次全失败，按机位写清前景和背景后 3 次都成功〔单一来源：drama-skills 实测〕。三人轮流说话的镜头容易放错说话人，文戏尽量用两人构图〔单一来源〕。
- 保持屏幕方向：角色从左侧入画、向右运动，就全片保持这个方向。镜头始终在两人连线的同一侧，用桌子、门、主桅这类固定物体锚定每个人的位置，每个镜头重复左右和视线方向〔官方〕。环绕超过约 90° 时，两人会在画面里互换左右；这位用户常用的 10–15° 短弧环绕，停稳时仍在原来一侧〔用户记录；推论〕。
- 热门运镜可以直接写：一镜到底、希区柯克变焦、航拍、FPV、子弹时间、手持、回弹变速。写的时候带上作用对象、起点、方向和终点〔官方〕。
- 小众术语要“翻译”：术语 + 作用主体 + 画面变化 + 前后景关系 + 方向或速度。焦距、光圈可以写，但直接描述看得见的结果更可靠（“背景虚化成柔和的光斑”比“f/1.4”更稳）〔官方〕。
- 转场写清触发的时间和方式（前景遮挡、甩镜、人物旋转、物体变形、推拉或焦点变化）。
- 更多术语见 `references/camera-and-sound.md`。用户常用镜头的写法见 `references/creator-profile.md` 第 3 节；打戏运镜和特写见 `references/combat-closeups.md`；按日式动画、电视剧、电影的方式排镜头见 `references/shot-grammar.md`。

### 表演和真实感

- 情绪写成看得见的表现。兽人先用耳朵、尾巴、视线、吻部和毛发，例如“凯尔的双耳先向后压了一下，又竖回来，视线移向窗外”；不写“脸红”“眼睛一亮”〔用户记录；官方要求写可观察的表现〕。耳尾动作的对照表见 `references/kemono-jp-drama.md` 1.6。
- 反应写成因果链：触发 → 停顿理解 → 第一反应 → 身体跟上 → 上一种情绪的余韵 → 结束状态。每一拍写 1–3 个当前景别看得清的细节，并写出幅度（“耳尖轻轻抖了一下”）。把眉、眼、鼻、嘴逐项列出来，会变成表情包式的切换〔多来源：官方 sd25-pe 与多个社区 skill 一致〕。
- 先因后果：人物因为某件事才变表情或动作时，先让观众看清原因，再给反应。原因和反应能同框，就放进同一个构图；隔得远，就用一次视线转移或镜头转移连起来。原因还没看清时，先别推成纯面部特写〔官方 sd25-pe〕。
- 停顿写成单独的时间段，里面写看得见的小动作和环境声，所有人闭着嘴；迟疑和打断用「……」「——」写进台词〔官方示例；停顿单独成段是推论〕。潜台词靠嘴上说的话和身体反应的反差来写〔推论〕。
- 强烈的情绪词（狂热、极度震惊、杀气）可能让眼睛发光：换成常规描述，再写眼睛本来的颜色和柔和的眼神光〔官方 FAQ〕。正向写法压不住时，才加官方原句“人物眼睛不发光”（负向写法，排障用）。
- 动作以概括为主，只给最有记忆点的一两下写细节，同一个动作只写一次〔官方〕。
- 静止的段落保留呼吸、毛发、衣料和环境的轻微动态，固定机位不等于画面冻结。毛发写清哪部分在动、往哪动，例如“微风从画外左侧吹来，凯尔颈部的长毛和耳尖的细毛顺着风轻轻颤动”〔推论〕。
- 要真实感，就写摄影语言：光源在画外哪一侧、浅景深、毛流方向和长短毛分区、衣服褶皱、环境里的日常杂物；人类角色写皮肤纹理。只写“逆光”会在头顶出光晕，改写成“主光源在画外左后方，在耳朵和肩膀边缘勾出细亮边”〔用户记录〕。

### 声音和对白

- 声音符号按官方：音乐 ()、音效 <>、台词 {}、字幕 【】〔官方：2.5 教程的符号规则，sd25-pe 相同〕。【】只做段落标签，台词只放 {}；用 <> 标音效时，角色名不加尖括号〔官方 sd25-pe〕。
- 台词行：`角色名（语言，音色，情绪，对谁说）：{台词原文}`，例如“凯尔（日语，冷酷大哥式的低沉男声，压低声音但有力，对杰拉德）：{……これは命令だ。}杰拉德闭着嘴静静听。”官方推荐“角色台词（情绪）：内容”，非中文台词在台词前写明语言，多个说话人逐个标注〔官方〕；“音色”和“对谁说”两栏是用户自己的写法〔用户记录〕。地区口音和方言只在用户指定时加〔官方 sd25-pe〕。
- 每句台词写在它发生的时间段或镜头里，全片只写一次；【声音】段只写“全片共 N 句台词”，不重复原文。
- 同一时间段只让一个人开口，其他在场的人写“闭着嘴静静听”；没有台词的段落，写在场的人闭着嘴〔官方 sd25-pe；本地实测：开头 0–1 秒多出过一句没写的话，待用户确认〕。台词放在听者的反应镜头上时，写“X（画外，日语，……）：{……}”，画面里的人闭着嘴〔推论〕。内心独白先写“X 的吻部闭合”，再写“X（V.O.，日语，……）：{……}”〔官方示例〕。
- 情绪、语气写在台词前的括号里。台词后面直接接下一个动作或“结束时”，不复述台词里的词，也不追加语气说明，官方 FAQ 说这样容易诱发字幕〔官方〕。
- 音量写“压低声音但有力”，不写“大声”（会抬高音高）；难读的汉字改写成假名（飯 → メシ）；台词里尽量别出现数字（怎么读各家说法冲突）；少念角色名，平台可能改写，还可能触发版权过滤〔用户记录；多来源〕。
- 时长：日语按拍（モーラ）估算，克制的文戏每秒 5–6 拍，每句再留约 1 秒，超过约 20 拍的句子拆进两个镜头；中文正常语速每秒 3–4 个字〔推论，依据见 `references/kemono-jp-drama.md` 2.3〕。官方说原生支持 10 余种语言，日语在内；2.0 技术报告里日语“按提示词说对”的得分低于英语，所以正式出片前先用 480P 试一句〔官方；多来源〕。
- 音效按物理来源写（“雨点打在铁皮屋顶上”“木门被拉开的吱呀声”），和动作写在同一秒；环境声写到最后一秒，否则后半段可能静音〔用户记录〕。
- 海上、雨夜、水下的戏，声音只写一两种具体声源（风、缆绳、木板吱呀），少写水、波浪、回音：官方 FAQ 说这类描述容易带出冒泡声和回声噪声〔官方〕。
- 字幕和配乐先用正向写法：“声音只有环境声、动作声和台词”“画面是纯净的影像，文字只出现在场景里原有的招牌上”〔用户记录〕。参考视频本身带字幕时，换一个没有字幕的素材；平台设置选横屏也会降低字幕概率〔官方〕。还是冒出来时，再加官方写法“画面不显示字幕”，或用视频编辑删除（负向写法，排障用）。

### 台词只用用户给的原文

- 用户给了台词原文：逐字照用，只补说话人、语言、音色、情绪和对谁说，不在前后补句子〔官方 sd25-pe〕。用户给的日文不改。
- 用户只给了说话意图（“凯尔劝杰拉德去休息”“两人吵起来”），没给原文：提示词里不写 {}，用动作、停顿、视线和对方的反应把这个意图拍出来，在场的人闭着嘴〔官方 sd25-pe〕。同时在回复的“台词草稿”里给 1–2 句符合角色语气的日文，标明“草稿，未写进提示词”，附中文意思和拍数；用户确认后，再放进 {}。
- 用户给的是中文台词、片子要说日语：译成符合角色语体的日语，放进 {}，在回复里附中文对照，标明“译稿，请确认”。这是翻译用户自己的台词，不算编造〔推论〕。
- 用户要求某角色开口、也绑了音色，却没给台词：保留“X 使用@音频N的音色说话”这一职责，台词写进“台词草稿”请用户补，不在提示词里编〔官方 sd25-pe〕。
- 角色设定里的原话（凯尔的「……これは命令だ。」、赛伦的「……もう一回。」等），只在剧本用到时才写进 {}。写杰拉德的台词前，先核对这一集他进化到了哪个阶段，不越级；读不到他的本地档案时，草稿里提醒用户核对〔用户记录〕。

### 编辑、延长和片段重拍

- **编辑**：提示词里要有“编辑视频 / 增加 / 删除 / 去掉 / 修改 / 替换 / 改成”之一〔官方〕。写法：先把原视频定为唯一母版 → 编辑目标 → 编辑范围（用时间戳限定）→ 保持原样的内容，最后加一句范围闭环：“除以上明确修改的对象外，@视频1中其他可见的人物、道具和背景元素全部保持原样”〔官方 sd25-pe〕。写清从 A 到 B 的变化过程。原视频在 20 秒以内效果较好，一次只改一项〔官方〕。只有一句日语读错时，用编辑只改这一句，示例见 `references/kemono-jp-drama.md` 2.5。
- **参考视频只当动作参考时**：上面那些词会把任务带成编辑，而编辑会锁定原视频的画幅和时长。所以写成“参考@视频1的打斗动作和镜头节奏，生成……”，人物外观另用图片绑定〔推论，依据官方的编辑触发词〕。参考视频的画幅或时长和目标不同时（例如 16:9 的排练视频配 21:9 的成片），在说明生成目标的那句后面，紧跟一句“请注意这不是视频编辑。”〔官方 sd25-pe〕。
- **延长**：提示词里要有“向前延长 / 向后延长 / 延续 / 续写”之一〔官方〕。向后延长先写原视频最后一帧的状态（姿态、道具、背景、机位、光线、声音、运动趋势），再写新内容；向前延长把原视频的第一帧写成延长片段的结束状态。写明每个主体始终是同一个连续对象，例如“凯尔一个、杰拉德一个，全程是同一个连续镜头”〔官方 sd25-pe〕。延长 Seedance 2.5 自己生成的视频衔接最自然，社区实测 3 次都无缝接上〔官方；单一来源〕。长对话适合用延长接成连续长镜头，打斗适合分段生成再剪〔官方 2.0〕。
- **片段重拍**（小云雀等平台）：只截取需要改的片段，一次只改一个点，片段越精准越省钱。
- 完整写法见 `references/templates-30s.md` 第 8 节。

### 超过 30 秒怎么办

拆成多条 30 秒以内的提示词，在自然的镜头边界处切开。每条都从 0 秒重新计时，都重新写画风行、角色行、服装和光线，并重新附上画面里每个角色自己的参考图，不写“同上一条”：模型看不到上一条〔用户记录〕。上一条的结束状态就是下一条的开始状态，有三种接法：

- 这位用户的做法：把上一条的末帧当普通参考图上传，写“@图片N（上条末帧）：只照两人的站位、朝向和镜头位置”〔用户记录〕。
- 要锁死开场画面：用首尾帧模式，把上一条的尾帧作为下一条的首帧（API 可以返回尾帧）；首帧决定画幅〔官方〕。
- 要动作无缝接上：直接对上一条用“向后延长”〔官方；单一来源实测〕。

## 平台与参数（截至 2026-10，以官方文档和平台界面为准）

- 入口：即梦、豆包、小云雀（Web 和 App），火山方舟 API（模型 ID `doubao-seedance-2-5-260628`），海外有 Dreamina / CapCut 和 BytePlus ModelArk。seedance.tv 这类同名网站和字节无关。
- 时长：4–30 秒，或设为 -1 让模型自选。画幅：21:9、16:9、4:3、1:1、3:4、9:16、adaptive。分辨率：480p、720p、1080p（App 内可以再超分到 4K）。输出 mp4 或 mov。
- 即梦网页（这位用户的主平台）：480P 样片 270 积分 / 30 秒，720P 600 积分；页面默认是“Seedance 2.5（样片模式）”，出正式片前要手动切换；一条约 6–10 分钟〔用户记录；本地实测〕。积分、报错和审核的处理见 `references/creator-profile.md`。
- API 的首尾帧模式和编辑、延长任务要求 `ratio` 为 `adaptive`；编辑任务的 `duration` 设为 -1，输出时长可能和原视频差约 0.3 秒，用 Seedance 2.5 自己生成的视频做编辑输入时没有差距〔官方〕。首尾帧用 `content.role` = `first_frame` / `last_frame` 会锁定画幅；改用 `reference_image` 再在提示词里点名首尾帧，不锁画幅，效果相近但不完全一致〔官方〕。
- 走 API 时，@图片N 的编号对应 content 数组里同类素材的先后顺序（以官方文档示例为准）。
- 用 Seedance 2.0 时：单次上限 15 秒，参考素材上限约 9 张图、3 段视频、3 段音频；2.0 不响应时间戳，只响应镜头序号，所以分镜写成“镜头1 / 镜头2”，时间轴压缩到 15 秒内〔官方；素材上限是第三方说法〕。
- 提示词长度：30 秒多镜头一般 800–1,500 字就够。官方 sd25-pe 不设字数上限，长了先压缩重复的风格词和约束。社区经验是过长、细节过多会生成得更慢，也更容易被审核拦截；平台截断或提示过长时，先删场景杂项和重复约束，保留素材分工、时间轴、结束状态和台词。

## 翻车排查

| 现象 | 常见原因 | 修复 |
|---|---|---|
| 中段重复动作、漂移 | 中段没有写相机动作或转折 | 给中段一个具体变化和一个明确运镜 |
| 一镜到底在两段交界被切开 | 段与段之间空间跳得远，或写了“镜头1/2/3” | 按时间段分段；第二段起每段开头写“镜头不停，继续……”，跨空间写出穿越路线；减到 3 段〔本地实测：第 7.38 秒〕 |
| 镜头比写的多 | 内容太密 | 合并次要事件，减少段数〔官方〕 |
| 角色变脸、两人混脸或互换 | 编号和出场顺序对不上；没写识别特征 | 按首次出场顺序上传并改编号；一行绑一个角色；每次提到都带上他独有的特征〔官方；用户记录〕 |
| 多出人物、重复人物 | 没写死人数 | “全片只有凯尔和杰拉德两个角色，每人在画面里各只有一个” |
| 兽人变成真动物、四肢着地、兽耳人类 | 下水、写了“半蹲”、只写了“狼兽人” | 写物种结构和具体姿势，见“兽人角色”〔用户记录〕 |
| 背景人物变成人类 | 只写了“路人”“客人” | 每个背景人物写种族〔用户记录〕 |
| 站位和视线错乱 | 只写了“隔桌相对”这类关系 | 每个镜头按机位写前景和背景，重复左右和视线方向〔单一来源实测〕 |
| 台词被错的角色说出、两张嘴一起动 | 同框却没写谁说、谁听 | 一段一人开口，其他人“闭着嘴静静听”；把台词挪到说话人的单人近景〔官方〕 |
| 开头多出一句没写过的话 | 开头段没交代在场的人闭着嘴 | 开头段写在场角色闭着嘴，【声音】写“全片共 N 句台词”〔本地实测，待用户确认〕 |
| 说话的音调偏高 | 写了“大声” | 改成“压低声音但有力”〔用户记录〕 |
| 日语读错 | 生僻汉字、数字、角色名 | 改写成假名；台词里避开数字；只错一句时用视频编辑改这一句 |
| 后半段没有声音 | 环境声没写到最后 | 环境声写到最后一秒〔用户记录〕 |
| 坐骑、宠物张嘴说话 | 有台词但没写说话人 | “台词只由骑手说；坐骑是普通的马，嘴巴自然闭合” |
| 只写在文字里的小细节偏了（黑书包变深蓝） | 文字描述压不过模型的默认 | 关键颜色和道具状态放进参考图，或在它入镜的镜头里再写一次〔本地实测；推论〕 |
| 字幕乱入 | 台词后追加了说明；参考视频带字幕；竖屏 | 情绪写在台词前；换无字幕素材；平台设置选横屏；还不行，再加官方句“画面不显示字幕”（负向写法，排障用），或用视频编辑删除〔官方〕 |
| 画面里冒出段落标题一样的字 | 段落标签用了【】（官方符号表里【】也表示字幕） | 把【】标签换成 ■ 或纯文字“画风：”〔多来源社区经验〕 |
| 背景音乐去不掉 | 默认会生成 | 先写“声音只有环境声、动作声和台词”；还不行，按官方 FAQ 在开头和结尾各写一遍音乐类同义词（音乐、背景音乐、BGM、配乐、器乐、旋律）的排除（负向写法，排障用）；或后期分离人声〔官方〕 |
| 眼睛发光 | 强烈的情绪词 | 换成常规描述，写眼睛的颜色和柔和的眼神光；还不行，再加“人物眼睛不发光”（负向写法，排障用）〔官方 FAQ〕 |
| 海上、雨中出现冒泡声或回声 | 写了水、波浪、回音 | 声音只写一两种具体声源（风、缆绳、木板吱呀）〔官方 FAQ〕 |
| 指纹状纹理 | 输入图分辨率高于输出 | 降低输入图分辨率〔官方〕 |
| 宫格分镜顺序乱、画面静止 | 宫格超过 15 格 | 控制在 15 格内，或改用多关键帧〔官方〕 |
| 延长后衔接跳变 | 没有描述原视频结尾的状态 | 先完整描述尾帧状态再写新动作〔官方〕 |
| 版权审核驳回 | 多半是某张全身参考图触发的 | 剔除那一张再试〔用户记录〕 |
| 复杂任务总是失败 | 一次塞了太多 | 拆成多次生成或编辑，后期再拼〔官方〕 |

## 边界

- 用真人照片或真人声音（包括声优）做参考时，提醒用户需要本人授权，平台审核也可能拦截；Seedance 2.5 不支持直接上传含真人人脸的参考图或视频〔官方〕。
- 只做原创角色：台词和提示词里不写现有动画、游戏的角色名；画风写看得见的特征，不写导演、工作室或作品名。角色写明“成年男性”。
- 打戏写成原创成年角色之间的舞台化武打：攻击落在剑身、护甲或格挡的手臂上，力道用火星、尘土、金属划痕和布料破口来表现，写“两人的毛发和衣服始终完整干净”；写法见 `references/combat-closeups.md` 第 7 节〔官方 sd25-pe；多来源〕。
- 被审核驳回时，先按误伤处理：删掉可能被误判的措辞（“嗜血、撕咬”这类词，“性感”这类概括词换成具体的剪裁和材质），剔除触发版权判定的参考图，再试〔多来源；用户记录〕。确认内容合规还是被拦，就走平台的反馈或申诉渠道。本技能不提供绕过人脸审核或内容审核的写法：人脸审核是防止未经同意把真人做进视频的，规避类写法还可能导致封号。
- 需要精确显示的文字、价格、公式和品牌标识，建议后期加，不要依赖模型生成。
- 本技能只负责写提示词，不默认替用户提交生成任务；平台的实际能力以当时界面和官方文档为准，不要虚构参数或语法。
